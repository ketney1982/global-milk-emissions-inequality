# outputs_R3 — the deposited artefacts of the R3 release

Everything in this directory is produced by the public entry point, from the frozen
inputs in `data/` plus `posterior_intensity_draws.npz`:

```bash
cp outputs_R3/posterior_intensity_draws.npz outputs/
python -m methane_portfolio.cli run-all --skip-bayes
python scripts/reproduce.py --no-run          # manifest + scope verification
```

That is the point of the release. R2 deposited correct results that the public
`run-all` did **not** regenerate: the sensitivity grid defaulted to the 20 largest
producers instead of the 181-country panel, and the optimiser exported one ambiguous
absolute-reduction column carrying a different quantity from the one the manuscript
reports. Both are fixed, and both are now pinned by tests
(`tests/test_manuscript_scope.py`).

## Relation to `outputs_R2/`

The numbers are the same. Compared against the R2 deposit, every shared quantity agrees
to machine precision — the portfolio results bit-for-bit, the 6,516-row grid to 9e-16 on
the absolute reduction (floating-point summation order) and exactly on everything else.
R3 changes how the artefacts are produced and named, not what they say:

| | R2 | R3 |
| --- | --- | --- |
| grid regenerated by `run-all` | 720 rows (20 countries) | **6,516 rows (181 countries)** |
| absolute reduction column | `absolute_reduction_kt`, holding the posterior-scaled figure in Mt | `abs_reduction_mt_ch4` (inventory-scaled, reported) **and** `abs_reduction_mt_ch4_posterior`, both in Mt, plus `observed_ch4_t` |
| `u_c_raw` convergence | not assessed | assessed; `u_c` assessed against the strict thresholds |
| posterior needed to re-run downstream | 1.6 GB archive | 3.5 MB draws file |
